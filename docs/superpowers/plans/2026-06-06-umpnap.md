# UMPNAP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A runnable C++/Qt6 process-network analysis platform with a validated single-phase hydraulic Newton-Raphson solver, a generic fluid property package, a plugin component library, a drag-and-drop P&ID editor, and trend plots.

**Architecture:** A Qt-free engine static library (`umpnap_engine` = core + solver + components) is consumed by both a CTest test suite and a Qt GUI app. The GUI only edits a `Network`; the `SolverManager` solves it. Nodal pressure formulation, Newton-Raphson with in-tree dense LU.

**Tech Stack:** C++17, Qt6 Widgets, CMake, CTest. No external math/plotting libs.

---

## Build order rationale

Engine first (LinAlg → core data model → fluids → components → solver → validation), each with unit tests that run without Qt. Then the GUI on top of the proven engine. This means the "prove it's real" validation passes before any GUI code exists.

## Task 6: Branch laws (flow given pressure drop) for hydraulic components

**Files:**
- Create: `src/components/hydraulic/BranchLaw.h`, `.cpp`
- Test: `tests/branchlaw_test.cpp`

A branch law computes flow `Q` (m³/s) and `dQ/d(dP)` for a two-port component given `dP = P_in - P_out` and the fluid. Boundary/Tank/Junction are nodes, not branches.
```cpp
// src/components/hydraulic/BranchLaw.h
#pragma once
#include "core/Component.h"
#include "core/FluidLibrary.h"
namespace umpnap {
struct BranchEval { double Q; double dQ_ddP; };
// dP = P_in - P_out (Pa). Returns volumetric flow in->out.
BranchEval evalBranch(const Component& c, double dP, const FluidProps& f);
bool isBranch(const std::string& type); // Pipe,Valve,Orifice,Pump,HeatExchanger
}
```
Laws (all flow forms invert `dP = K*Q*|Q|` → `Q = sign(dP)*sqrt(|dP|/K)`, with `dQ/ddP = 1/(2*sqrt(K*|dP|))` guarded near zero by a small linear region `|dP|<eps`):
- **Pipe:** Compute `K` from Darcy-Weisbach. Because `f` depends on `Re(Q)`, use a fixed-friction linearization per evaluation: start with turbulent `f` via Swamee-Jain at a reference velocity, `A=π d²/4`, `K=f*(L/D)*ρ/(2A²)`. (Iteration on `f` happens through the outer Newton loop re-evaluating.) Provide `frictionFactor(Re, rel_rough)`: laminar `64/Re` for Re<2300 else Swamee-Jain.
- **Valve:** `K = Kv / max(position,1e-3)²` scaled to SI (treat Kv as a resistance coefficient: `K_eff = Kv/position² * ρ`). 
- **Orifice:** `A=π bore²/4`, `K = ρ/(2 Cd² A²)`.
- **Pump:** `dP_pump(Q) = ρ g (H0 - a Q²)`; residual form `Q = sign(...)`. Implement as: given `dP` (= P_in-P_out, negative across a pump that adds head), solve `ρ g (H0 - a Q²) = -dP` → `Q = sqrt(max((H0 + dP/(ρg))/a, 0))`. Derivative via implicit diff.
- **HeatExchanger:** `K = K_hx * ρ` (fixed resistance), same sqrt form.

Helper for the common quadratic-resistance branch:
```cpp
// Q = sign(dP) * sqrt(|dP|/K); linearized for |dP| < eps to keep Jacobian finite.
BranchEval resistanceFlow(double dP, double K, double eps = 1.0);
```

- [ ] **Step 1:** `tests/branchlaw_test.cpp`: for an Orifice with default params and water, `evalBranch` at `dP=1e4` gives `Q>0`, at `dP=-1e4` gives `Q<0` and symmetric magnitude; `Q*Q*K ≈ |dP|`; derivative positive; near `dP=0` derivative finite (no div-by-zero). Pump at `dP` such that head is positive gives `Q>0`.
- [ ] **Step 2:** Build/run → FAIL.
- [ ] **Step 3:** Implement `resistanceFlow`, `frictionFactor`, and `evalBranch` switching on type.

Builds the solver topology: union-find over ports joined by connections and by Junction internal ports, producing nodes; classifies each node as `Free`, `Fixed` (Boundary/Tank pressure), and lists branches `(component, inNode, outNode)`.
```cpp
// src/solver/NodeGraph.h
#pragma once
#include "core/Network.h"
#include <map>
#include <vector>
namespace umpnap {
struct Branch { int compId; int inNode; int outNode; };
struct NodeGraph {
  int nodeCount = 0;
  std::vector<bool> fixed;          // size nodeCount
  std::vector<double> fixedP;       // pressure if fixed (else 0)
  std::vector<Branch> branches;
  std::map<std::pair<int,std::string>,int> portNode; // (compId,port) -> node

NodeGraph buildNodeGraph(Network& net); // pressures for Tank computed from level
```

HydraulicSolver::solveSteady:
1. `buildNodeGraph`. Map free nodes → unknown index.
2. Newton: assemble residual `F[i] = Σ branch flows signed into free node i`; Jacobian `J[i][j] = dF_i/dP_j` from each branch's `dQ_ddP` (in/out node contributions, signs). Fixed nodes use fixed pressure.
3. `lu_solve(J, -F)` → ΔP, update free pressures, damping factor 1.0 (halve if residual rises), tol `1e-6` on max |F|, max 100 iters.
4. On convergence record: each node pressure `node.N.pressure`, each branch `comp.<id>.flow` (m³/s), plus derived signals — Pump `comp.<id>.head` (m), Valve `comp.<id>.position`, Tank `comp.<id>.level`.

SolverManager: holds registered solvers; `runSteady(net, results)` dispatches to hydraulic; `runTransient(net, results, dt, steps)` loops: solve steady, then integrate each Tank `level += dt * Qnet/area` (Qnet from the branch flow at the tank port), record at each `t`.

## Task 9: Validation case — series + parallel network vs analytical

**Files:**
- Create: `src/solver/Validation.h`, `.cpp` (builds the canonical case + returns max error)
- Test: `tests/validation_test.cpp`

Canonical case (all water, all Orifices so K is exact and friction-independent):
- Boundary A `P=3e5` → Orifice O1 (K1) → node M.
- From M two parallel Orifices O2 (K2), O3 (K3) → node N.
- N → Orifice O4 (K4) → Boundary B `P=1e5`.

Analytical: equivalent resistance of the quadratic-resistance branches. For each branch `Q = sqrt(ΔP/K)`. Parallel branches share the same ΔP_MN, so total `Q = Q2+Q3 = (1/√K2 + 1/√K3)·√ΔP_MN`; define `K_par` s.t. `Q = √(ΔP_MN/K_par)` → `1/√K_par = 1/√K2 + 1/√K3`. Series add in the `√K` domain only loosely (nonlinear), so solve the 1-D analytical: total flow `Q` satisfies `3e5-1e5 = (K1 + K_par + K4)·Q²` ⇒ `Q = √(2e5/(K1+K_par+K4))`. Back out node pressures. Provide `analyticalSolution()` returning expected `Q`, `P_M`, `P_N`.
